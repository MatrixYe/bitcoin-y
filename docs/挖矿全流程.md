
源代码流程：
`GenerateBitcoins` -> `ThreadBitcoinMiner` -> `BitcoinMiner` -> `CreateNewBlock` -> `ScanHash` -> `CheckWork` -> `ProcessBlock`/`AcceptBlock`

按 v 0.3.19 的 `[main.cpp](main.cpp)` ，这个版本的挖矿逻辑基本集中在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:2919) 后半段，现代 Bitcoin Core 里的 `getblocktemplate`、矿池协议、独立 mining 模块都还不存在。

开启挖矿线程，构造候选区块，选择交易，生成 coinbase，计算 Merkle root，准备区块头哈希缓冲区，反复扫描 nonce，找到满足目标的哈希后，把自己挖出的区块当作网络收到的普通区块走同一套验证和入链流程。
```text

GenerateBitcoins()
  -> ThreadBitcoinMiner()
  -> BitcoinMiner()
  -> CreateNewBlock()
  -> IncrementExtraNonce()
  -> FormatHashBuffers()
  -> ScanHash_CryptoPP() / ScanHash_4WaySSE2()
  -> CheckWork()
  -> ProcessBlock()
  -> AcceptBlock()
  -> AddToBlockIndex()
  -> SetBestChain()
```

## **3. 创建候选区块**

## **6. 难度目标 nBits 的来源**
`nBits` 来自 [GetNextWorkRequired](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:930)。
普通高度直接沿用上一个区块：

```cpp
if ((pindexLast->nHeight+1) % nInterval != 0)
    return pindexLast->nBits;
```
每 2016 块重算一次：
```text
目标周期：14 天
目标间隔：10 分钟
nInterval = 2016
```
实际时间会被限制在 `[目标时间 / 4, 目标时间 * 4]`，然后：
```cpp
bnNew = old_target * nActualTimespan / nTargetTimespan;
```
最后不能超过 `bnProofOfWorkLimit`。主网的上限在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:25)：
```cpp
CBigNum bnProofOfWorkLimit(~uint256(0) >> 32);
```

## **7. ExtraNonce 扩展搜索空间**

创建区块后，`BitcoinMiner()` 立刻调用：
```cpp
IncrementExtraNonce(pblock.get(), pindexPrev, nExtraNonce, nPrevTime);
```
实现是 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3278)：
```cpp
pblock->vtx[0].vin[0].scriptSig = CScript() << pblock->nBits << CBigNum(nExtraNonce);
pblock->hashMerkleRoot = pblock->BuildMerkleTree();
```
这点很关键：`nNonce` 只有 32 位，不够长期搜索。于是早期 Bitcoin 通过修改 coinbase 的 `scriptSig` 里的 extra nonce 改变 coinbase txid，进而改变 Merkle root，最终改变区块头。每次 Merkle root 变化，都相当于换了一个新的 nonce 搜索空间。

## **8. 准备 SHA 256 哈希缓冲区**
区块哈希是双 SHA 256。正常路径在 [main.h](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.h:1099)：
```cpp
return Hash(BEGIN(nVersion), END(nNonce));
```

挖矿时为了快，不每次完整序列化和完整 SHA 256，而是用 [FormatHashBuffers](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3292) 预处理。它构造一个只包含区块头的结构：
```cpp
int nVersion;
uint256 hashPrevBlock;
uint256 hashMerkleRoot;
unsigned int nTime;
unsigned int nBits;
unsigned int nNonce;
```
这正好是 80 字节区块头。然后：
1. 用 `FormatHashBlocks()` 做 SHA 256 padding。
2. 对 32-bit word 做 `ByteReverse()`，因为底层扫描函数按 big-endian 数据工作。
3. 预计算第一轮 SHA 256 的前半部分 midstate：
```cpp
SHA256Transform(pmidstate, &tmp.block, pSHA256InitState);
```

区块头 80 字节会被 SHA 256 padding 成两个 64 字节块。前 64 字节在一个候选区块内基本不变，所以可以提前算 midstate；循环里主要变的是第二个 64 字节块里的 `nTime` 和 `nNonce`。

## **9. 扫描 nonce**

主搜索循环在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3439)。

每轮调用：
```cpp
ScanHash_CryptoPP(pmidstate, pdata + 64, phash1, (char*)&hash, nHashesDone);
```

或者 SSE 2 版本：
```cpp
ScanHash_4WaySSE2(…)
```

普通实现是 [ScanHash_CryptoPP](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3067)。
核心逻辑：

```cpp
nNonce++;
SHA256Transform(phash1, pdata, pmidstate);
SHA256Transform(phash, phash1, pSHA256InitState);
```

这就是双 SHA 256 的优化版：第一轮用预计算好的 `pmidstate` 接着 hash 第二个块，得到 `hash1`；第二轮 hash `hash1` 得到最终 `phash`。注意它不是每个 nonce 都完整比较 target，而是先做一个粗筛：
[main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3079)

```cpp
if (((unsigned short*)phash)[14] == 0)
    return nNonce;
```
意思是：只有当结果看起来至少有一些零位时，才返回给外层做完整目标比较。否则每 65536 次返回一次 `-1`，让外层更新 hashmeter 和检查是否要重建区块。

## 10.**完整检查候选 hash**
`ScanHash` 找到候选 nonce 后，外层先做字节序转换：
```cpp
for (int i = 0; i < sizeof(hash)/4; i++)
    ((unsigned int*)&hash)[i] = ByteReverse(((unsigned int*)&hash)[i]);
```

然后比较：
```cpp
if (hash <= hashTarget)
```

如果满足：
```cpp
pblock->nNonce = ByteReverse(nNonceFound);
assert(hash == pblock->GetHash());
CheckWork(pblock.get(), reservekey);
```

这里 `assert` 很重要：优化扫描路径得到的 hash 必须等于普通 `CBlock::GetHash()` 路径算出的 hash。

## **11. 找到块后的 CheckWork**
[CheckWork](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:3338) 先重新算一次：
```cpp
uint256 hash = pblock->GetHash();
uint256 hashTarget = CBigNum().SetCompact(pblock->nBits).getuint256();

if (hash > hashTarget)
    return false;
```

然后进入 `cs_main`，检查 stale：
```cpp
if (pblock->hashPrevBlock != hashBestChain)
    return error("BitcoinMiner : generated block is stale");
```
如果在挖矿期间别人已经扩展了最佳链，这个块就过期了。
```cpp
reservekey.KeepKey();
mapRequestCount[pblock->GetHash()] = 0;
ProcessBlock(NULL, pblock);
```
`KeepKey()` 表示这次 coinbase 真的用了这个预留密钥，不再放回 keypool。然后把自己挖出的区块交给 `ProcessBlock()`，和网络收到的区块走同一条验证路径。

## **12. 本地区块验证与入链**
[ProcessBlock](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1584) 先查重复，再调用：

`CheckBlock()` 在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1492)，检查:
```text

PoW 是否满足 nBits
```

`AddToBlockIndex()` 在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1438)，创建 `CBlockIndex`，设置高度、前驱、累计工作量：

`GetBlockWork()` 在 [main.h](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.h:1342)：

如果累计工作量超过当前最佳链，就调用 [SetBestChain](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1383)。

## **13. 连接到最佳链**
如果新块直接接在当前 best 后面：
```cpp
if (hashPrevBlock == hashBestChain)
```
就调用 `ConnectBlock()`。`ConnectBlock()` 在 [main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1248)，它会逐笔交易调用 `ConnectInputs()`，真正更新交易索引和 spent 状态，并累计手续费。最后检查 coinbase 没有多拿：
```cpp
if (vtx[0].GetValueOut() > GetBlockValue(pindex->nHeight, nFees))
    return false;
```

连接成功后，`SetBestChain()` 更新全局最佳链状态：
```cpp
hashBestChain = hash;
pindexBest = pindexNew;
nBestHeight = pindexBest->nHeight;
bnBestChainWork = pindexNew->bnChainWork;
```
同时从 mempool 删除已经进入区块的交易：
[main.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/main.cpp:1410)。

如果新块不是直接接在当前 best 上，但累计工作量更大，就走 `Reorganize()`，断开旧分支、连接新分支。挖矿自己产出的块通常是接 best 的，但源码仍然统一支持重组路径。

## **14. 什么时候重建候选区块**
挖矿内循环不会永远扫同一个候选块。以下情况会跳出内层循环，回到外层重建区块：
```text
fShutdown
fGenerateBitcoins 关闭
线程数超过限制
没有连接节点
nonce 接近 0xffff0000
mempool 更新并且已经挖了超过 60 秒
pindexBest 变化，也就是链 tip 变了
```
另外每轮都会更新时间：
```cpp
pblock->nTime = max(pindexPrev->GetMedianTimePast()+1, GetAdjustedTime());
nBlockTime = ByteReverse(pblock->nTime);
```
所以在同一个候选区块的搜索过程中，`nTime` 也会前进。

## **15. RPC Getwork 旁路**
v 0.3.19 还有一个相关路径：`[rpc.cpp](rpc.cpp)` 的 `getwork`。它不是独立挖矿逻辑，而是复用同一套函数。
 
在 [rpc.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/rpc.cpp:1066)，无参数 `getwork` 会：

```cpp
CreateNewBlock(reservekey);
IncrementExtraNonce(…);
FormatHashBuffers(…);
返回 midstate/data/hash1/target;
```

矿工提交结果时，[rpc.cpp](/Users/yepeng/Codes/Rust/bitcoin-y/bitcoin/rpc.cpp:1108) 会 byte reverse 数据，找回缓存的 block，设置 `nTime` 和 `nNonce`，最后调用：
```cpp
return CheckWork(pblock, reservekey);
```

也就是说，内置 CPU 挖矿和 RPC 外部挖矿最终都汇入 `CheckWork -> ProcessBlock -> AcceptBlock -> SetBestChain`。

## 总结
v 0.3.19 的挖矿是一个内置在节点里的 solo CPU miner：节点从自己的 mempool 按 priority 组装候选区块，用钱包预留 key 生成 coinbase，靠 extra nonce 改 Merkle root 扩展搜索空间，预计算 SHA 256 midstate 后扫描 `nNonce`，找到 `hash <= target` 后，把区块交给完整区块验证和入链逻辑处理，最后更新最佳链、钱包、mempool，并向网络广播新区块 inventory。
