# 数值关系

## rust中的整数范围

### 无符号整数（u 开头，只包含非负数）

- **u8**: 0 ~ 255
- **u16**: 0 ~ 65535
- **u32**: 0 ~ 4294967295
- **u64**: 0 ~ 18446744073709551615
- **u128**: 0 ~ 340282366920938463463374607431768211455

### 有符号整数（i 开头，包含正负）

- **i8**: -128 ~ 127
- **i16**: -32768 ~ 32767
- **i32**: -2147483648 ~ 2147483647
- **i64**: -9223372036854775808 ~ 9223372036854775807
- **i128**: -170141183460469231731687303715884105728 ~ 170141183460469231731687303715884105727

### 特殊usize

- **usize / isize**: 位数跟随系统（32位/64位）
- 公式：`uN` 范围 `0 ~ 2ⁿ-1`，`iN` 范围 `-2ⁿ⁻¹ ~ 2ⁿ⁻¹-1`

## BigNum

BigNum的特征：任意精度、有符号，适合脚本 Numeric。

uint256特征：固定 256 位、无符号、小端字序，适合哈希、目标值、PoW 比较。

原版 bignum.h 的核心不是自己手写大整数算法，而是对 OpenSSL BIGNUM 做了一层 C++ 封装：class CBigNum : public BIGNUM。它把 OpenSSL 的大整数能力包装成比特币脚本和区块难度计算都能使用的 CBigNum 类型。
它实现的主要功能
1、整数构造与转换
```cpp
CBigNum(int n)
CBigNum(int64 n)
CBigNum(uint64 n)
CBigNum(uint256 n)
CBigNum(const std::vector<unsigned char>& vch)
```
把普通整数或字节数组转成 OpenSSL BIGNUM。

2、ScriptNum 字节格式互转
原版脚本栈里的数字是 vector<unsigned char>，也就是字节数组。CBigNum 通过两个函数和它互转：

i64 方案只是“能跑”，不是原版语义。原版 Numeric 的核心不是 int64，而是

```cpp
void setvch(const std::vector<unsigned char>& vch)
std::vector<unsigned char> getvch() const

```

3、数值规范化
```cpp
CBigNum CastToBigNum(const valtype& vch)
{
    if (vch.size() > nMaxNumSize)
        throw runtime_error("CastToBigNum() : overflow");
    return CBigNum(CBigNum(vch).getvch());
}

```
输入脚本数字最多 4 字节，这是脚本规则，不是 CBigNum 自己的限制。CBigNum(vch).getvch() 会把数字重新编码，去掉多余的前导零，得到规范化 ScriptNum。
所以 bignum.h 不负责 MAX_SCRIPT_NUM_SIZE = 4，这个限制是在 script.cpp 的 CastToBigNum 中加的。

这就是原版 Numeric 操作码为什么可以不依赖 i64：所有计算都发生在 OpenSSL 大整数上。

6、特殊的右移逻辑
```cpp
CBigNum a = 1;
a <<= shift;
if (BN_cmp(&a, this) > 0)
{
    *this = 0;
    return *this;
}
BN_rshift(this, this, shift);

```
注释说这是为了规避某些 OpenSSL 版本下 BN_rshift 的崩溃问题。
原版 OP_RSHIFT 不是简单等价于 Rust i64 >> shift。尤其是负数、超大 shift 这些边界行为，直接用 i64 很难完全复刻。

7、区块难度相关 compact 格式
bignum.h 还实现了：
```cpp
SetCompact(unsigned int nCompact)
GetCompact()

```
这是区块难度目标值 nBits 的 compact 编码/解码逻辑，主要服务于 PoW 难度，不是脚本 Numeric 操作码的核心需求。


----
```cpp
CBigNum bn = CastToBigNum(stacktop(-1));
...
stack.push_back(bn.getvch());

```

所以应该把 Numeric 从 i64 重构成一个真正的“大整数脚本数值层”。
关键语义 CastToBigNum 有两个重点：
1、输入栈元素最多 4 字节：

```cpp
if (vch.size() > nMaxNumSize)
    throw runtime_error("CastToBigNum() : overflow");

```

2、计算结果不是 4 字节限制。
OP_LSHIFT 可以把一个 4 字节以内的输入左移很多位，结果可能远超 i64，然后通过 bn.getvch() 压回栈。下一次如果再把这个超 4
字节结果当数字读取，CastToBigNum 才会失败。
