大小端只是在回答一个问题：**一个多字节数字，最低位字节放前面，还是最高位字节放前面。**

假设有一个十六进制数字：

```text
0x12345678
```

它有 4 个字节：

```text
12 34 56 78
```
```text
大端：大的一端先放，高位字节在前。
小端：小的一端先放，低位字节在前。
```
**大端序 Big-endian**

大端序就是“高位在前”：

```text
12 34 56 78
```

像我们平时写数字一样，从大到小写。  
所以：

```text
0x12345678 -> [0x12, 0x34, 0x56, 0x78]
```

**小端序 Little-endian**

小端序就是“低位在前”：

```text
78 56 34 12
```

所以：

```text
0x12345678 -> [0x78, 0x56, 0x34, 0x12]
```

对比：

```text
数字：0x12345678

大端：[12, 34, 56, 78]
小端：[78, 56, 34, 12]
```

**用十进制理解**

假设数字是：

```text
258
```

十六进制是：

```text
0x0102
```

它由两个字节组成：

```text
01 02
```

大端：

```text
[0x01, 0x02]
```

意思是：

```text
0x01 * 256 + 0x02 = 258
```

小端：

```text
[0x02, 0x01]
```

意思是：

```text
0x02 + 0x01 * 256 = 258
```

所以小端不是改变数字本身，只是改变字节排列顺序。

**和 Bitcoin Script 数字的关系**

Bitcoin Script 数字使用小端表示。

例如：

```text
1  -> [0x01]
2  -> [0x02]
16 -> [0x10]
```

这些只有一个字节，所以大小端看不出区别。

但如果是：

```text
256 = 0x0100
```

大端会写成：

```text
[0x01, 0x00]
```

Bitcoin Script 小端写成：

```text
[0x00, 0x01]
```

再比如：

```text
258 = 0x0102
```

Bitcoin Script 小端是：

```text
[0x02, 0x01]
```

**为什么 128 是 `[0x80, 0x00]`**

数字 128 是：

```text
0x80
```

如果只写一个字节：

```text
[0x80]
```

在 Bitcoin Script 数字里，最后一个字节的最高位是符号位。`0x80` 的最高位是 1，所以它会被理解成负号相关的值，不是正 128。

所以正 128 要补一个 `0x00` 作为最高字节：

```text
[0x80, 0x00]
```

因为它是小端：

```text
低字节 0x80 在前
高字节 0x00 在后
```

最后一个字节 `0x00` 的最高位不是 1，所以这是正数。

所以：

```text
[0x01]       = 1
[0x81]       = -1
[0x00,0x01]  = 256
[0x80,0x00]  = 128
```
