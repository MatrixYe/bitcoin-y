# 解决分叉的方式


## 自然分叉
高度一样、累计链工作量也一样时如何处理 如果系统出现两个区块：

```text
        B1
       /
G -> A
       \
        B2

```
此时`B1.height == B2.height`,`B1.chain_work == B2.chain_work`
比特币原版的处理原则非常简单：
```cpp
if (pindexNew->bnChainWork > bnBestChainWork)
    SetBestChain(...)

```
注意是大于，不是大于等于！！！！所以如果新区块累计工作量等于当前最佳链累计工作量，原版不会切换。先成为 best 的链继续保持 best
后来的同等工作量分支保留为 side branch。这是一种非常重要的稳定性规则。否则如果使用 >=，节点可能因为同等工作量分支来回切换，导致不必要的重组。
所以在我写的版本中`add_header`的实现逻辑是:
```rust
self.indexes[&hash].chain_work > best.chain_work
```
所以区块树里应该这样处理：
1. 两个区块都存进 indexes。
2. 两个区块都挂到同一个父块的 children 下。
3. best_hash 不变。
4. active_chain 不变。
5. next 指针不变。
6. 后来的同工作量区块作为 side branch 保存。


## 高级分叉，切换最佳链

1. 新区块所在分支累计工作量超过当前 best chain，需要链重组。
2. 响应对端 getblocks/getheaders 时，判断双方共同祖先。
3. 构造 block locator 时，辅助定位本地链和远端链的交叉点。
4. 检查某条 side chain 是否有机会成为新主链。
5. 后续实现 DisconnectBlock / ConnectBlock 时，确定断开和连接范围。
