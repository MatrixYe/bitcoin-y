# 区块树的设计(内存版)


原版的BlockIndex 设计字段
```cpp
 const uint256* phashBlock;
 CBlockIndex* pprev;
 CBlockIndex* pnext;
 unsigned int nFile;
 unsigned int nBlockPos;
 int nHeight;
 CBigNum bnChainWork;

 // block header
 int nVersion;
 uint256 hashMerkleRoot;
 unsigned int nTime;
 unsigned int nBits;
 unsigned int nNonce;
 ```
pprev 表示父块，所有分叉都通过它形成树；pnext 不是“所有子节点”，而是当前最佳链上的下一块。持久化时，裸指针不能直接写入数据库，所以原版使用 CDiskBlockIndex 把指针转成 hash。

总结一下原版模型：

磁盘:
blkNNNN.dat       -> 原始区块数据，追加写
blkindex.dat      -> 区块索引、交易索引、最佳链 hash 等 Berkeley DB KV 数据

内存:
mapBlockIndex     -> hash 到 CBlockIndex*
pprev             -> 父块指针
pnext             -> 当前最佳链的下一块
pindexBest        -> 当前最佳链 tip
bnBestChainWork   -> 当前最佳链累计工作量

> 我不想使用裸指针表达区块数，也不想用文件相关字段暴露在共识的核心字段，更讨厌将存储是现在一个老旧的KV数据库中，为了模仿而把存储格式设计成难以调试的二进制数据。！！！
